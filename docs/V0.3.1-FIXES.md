# AI1 Emu v0.3.1 — DS startup and artwork folder fixes

The v0.3.0 DS integration produced a black screen on the user's Switch. The exact device failure has not yet been captured. This build addresses identified startup weaknesses and adds useful diagnostics; it is a candidate for hardware retesting, not a claim that the reported failure has been reproduced or resolved on Switch.

Changes:

- Read ROMs in bulk chunks, with Plus+Minus cancellation during reads, instead of a byte-at-a-time vector constructor.
- Display the current loading stage rather than leaving a blank screen throughout startup.
- Record stages, core messages, ROM byte count, first frame returns and failures in `switch/ai1emu/logs/core-nds.log` (or the active legacy data folder). DSi uses `core-dsi.log`.
- Propagate actual firmware and cartridge load errors. Preserve the intentional DS direct-boot FreeBIOS/generated-firmware fallback; reject malformed supplied firmware. The core previously ignored the firmware setup result and cartridge load result.
- Disable strict aliasing for the old core's type-punned C++ code. Use software rendering with its worker disabled, keep the interpreter and disable host networking in the Switch build.
- Poll Plus+Minus from within DS CPU frame loops, using separate controller state so state-save/load button transitions are retained. A frame over five seconds can abort cooperatively. Low-level driver hangs cannot be recovered through that hook.
- Flush pending DS SRAM on unload.
- Require application/full-memory mode for DS before launching. The existing HOME tile is the intended route.
- Correct DBI folder selection: all supported extensions and nested folders count when preferring `ai1emu` over `retroverse`. Both nonempty folders now prefer `ai1emu`, matching the app. The tool prints its chosen folder. Custom artwork remains untouched.

Install the complete `AI1-Emu-v0.3.1-Switch-Package.zip`: merge its `switch` folder into the SD root, replacing the main NRO and all four companion NROs. Keep existing ROMs, saves and covers. Replace old PC-tools with this package's copies. For DBI, run `PC-tools/AI1Emu-Automatic-Covers-DBI.cmd`; no Node.js is needed. For an SD reader, run `PC-tools/Prepare-Artwork.cmd`.

Validation: Switch main app and all companions compiled and linked. The actual DS software core was also built separately on Windows and loaded a synthetic, self-authored DS program. Twelve video frames and audio sample callbacks, save-state serialization/restoration, and unload passed. Deliberately invalid BIOS data returned a load failure. These tests do not prove audible output, commercial-game compatibility or Switch performance. Artwork tests cover every console's folder choice, nested ROMs, both folders populated, legacy fallback, empty folders, offline matching, checksum matching and custom-cover preservation.

After installation, try one DS game. If it still stalls, note the loading stage and retrieve `switch/ai1emu/logs/core-nds.log` after closing AI1 with HOME. That identifies whether the failure is before ROM read, during core load or during frame execution. No keys, ROMs, firmware or commercial covers are bundled, and stable Cloudflare v0.2.2 remains unchanged.
