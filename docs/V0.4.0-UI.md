# AI1 Emu v0.4.0: library UI redesign

v0.4.0 changes the library interface only. Emulator cores, chainloading, saves,
states, the online updater and migration are unchanged, and the companion core
NROs do not need rebuilding. Build the main app as usual (`scripts/build-switch.sh`).

## What changed

- New visual language, matching the AI1 Emu site: ink background, ultramarine
  header, lime/pink/orange accents and one colour per console.
- New fonts in `romfs/`: Unbounded ExtraBold (display), Geist Regular and
  SemiBold (body), Geist Mono Medium (labels). They are static instances subset
  to Latin-1 (32-255, the range the stb_truetype baker already uses), 15-34 KB
  each. SIL OFL 1.1 texts are in `licenses/` and `romfs/`. DejaVu Sans stays in
  `romfs/` as the fallback if a font file is missing.
- Font atlases are sized per family and size (256x256 up to 22 px, 512x512 up to
  48 px, doubling if a bake does not fit). Visiting every tab bakes 31 atlases,
  13.8 MB of textures, against 15 atlases and 15 MB in v0.3.5.
- Five tabs instead of three. Visual order: Games, Map, Controls, Settings, About.
  Tab ids keep their v0.3 meaning (0 Games, 1 Settings, 2 About); Map is 3 and
  Controls is 4. L/R now call `LibraryUI::cycleTab()`.
- **Games:** console chips show each console's colour, cards without artwork get
  a console-coloured gradient with initials, and the details panel shows a
  "No-Intro match" or "Not in the table" badge (`gameRecognized()` in
  `game_database.cpp`). Carousel geometry and touch targets are unchanged.
- **Map:** one dot per release in the bundled No-Intro tables (40,277 across 11
  consoles), in proportional blocks per console. Games on the current shelf are
  drawn bright; the selected game pulses with its title. Left/Right move the
  selection. The tables are parsed on first open (one "Loading" frame, then a
  one-time parse: 39 ms on a desktop x86 core). The dots are drawn with one
  batched `SDL_RenderFillRects` call per console, 11 calls a frame.
- **Controls:** a controller diagram that lights up whatever is held, including
  stick tilt, next to the library and in-game button maps. Every button is
  captured on this tab except B, which returns to Games. Touch still switches tabs.
- **Settings:** same rows and touch bands, restyled as toggles and an update card.
- **About:** app card plus "Your SD card", a treemap of the active data folder
  (ROMs per console, saves, quick states, artwork, screenshots, metadata, BIOS,
  cores, app). It is measured once per session on an SDL thread. `~LibraryUI()`
  sets `storageStop` and joins the thread, so quitting or launching a game never
  waits for the walk to finish. The worker avoids `detectPlatform()` and the
  other caches, so it shares no mutable state with the UI thread.
- Footer hints and touch footer actions are per tab (`library_touch.cpp`).
- Fix: `text()` used to disable clipping when its rectangle missed the active
  clip rectangle (SDL2 treats an empty clip as "no clip"), so off-screen card
  text could draw outside the carousel. It now skips fully clipped text.

## Frontend changes (`main.cpp`)

- Copies held buttons and both stick positions into `ui.padHeld` / `ui.stick*`.
- Controls tab: draws and `continue`s before the library input; B returns to Games.
- X and Y act only on Games and Settings; A launches only from Games;
  Left/Right also move the selection on Map.

## Verified here (not on a Switch)

- `windows_preview.cpp --capture` tours every screen (8 captures). It builds on
  Linux against the bundled SDL2 2.28.5 with the offscreen driver:
  `scripts/build-linux-preview.sh`.
- Host tests pass: touch (updated for five tabs and the per-tab footer),
  yellow artwork (renders the new UI in a software renderer), platform, library
  duplicates, update manifest, update install and migration.
- `main.cpp` type-checks against libnx stubs; it has not been compiled with devkitA64.

## Not verified

- Switch build, frame pacing and memory on hardware, glyph rendering on the
  Switch GPU path, and touch on a real screen.
- If the Map tab drops frames on a Switch, render the dot field into a target
  texture once per shelf change and copy it each frame.
