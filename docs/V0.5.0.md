# AI1 Emu v0.5.0: redesign and in-game menu

v0.5.0 rebuilds the library on a new drawing kit and adds an in-game menu to every
emulator. Emulator cores, save files and the folder layout are unchanged. Existing
quick states (`.state`) keep working as Slot 1.

## What's new

### Library

- **Three tabs: Home, Library, Settings.** Map, Controls and About moved into Settings.
- **Home:** the last game you played with **Resume**, which continues from the
  automatic save made when you quit, and **Start over**. Next to it are your three
  most recent games, with your whole collection on a shelf below.
- **Library:** a 5-column grid with search (Switch keyboard), favourites (Y), console
  filters (ZL/ZR), sorting (−: recently played, A–Z, Z–A, most played) and a details
  panel showing play time, last played, save states and cheats.
- **Settings:** Library, Gameplay (defaults for every game), Controls, Themes, Updates,
  Game map and About & SD card.
- **Themes:** White (default), Black, Ocean, Sakura, Forest and Night. *Make your own*
  sets the accent colour, background (plain, or `themes/wallpaper.png`/`.jpg`), font
  (Rounded, Rubik or Nunito) and corner style. **X saves it** as
  `themes/my-theme.theme`, which then appears as a theme card.
- **Look:** new fonts (M PLUS Rounded 1c by default), anti-aliased rounded shapes and
  vector icons, and a pulsing selection cursor. Covers without artwork get a tile
  coloured by console.
- Play time and history are kept in `history.txt` and favourites in `favorites.txt`.
  On first start, v0.4 `.lastplayed` stamps are imported so Home is not empty.

### In-game menu (every console)

Open it with **+ and − pressed together**, or tap the top-right corner of the touch
screen on consoles without a touch screen of their own. While it is open the game is
paused and muted.

| Item | What it does |
| --- | --- |
| Resume | Back to the game (B also resumes) |
| Save state | 5 manual slots, each with a picture and time. Replacing a save asks first. Y deletes. |
| Load state | The 5 slots plus the **automatic save** made when you quit. X undoes the last load. |
| Rewind | On or off. Hold **L3** while playing to go back up to 20 seconds. |
| Speed | Fast forward 1.5×–4× (**R3**, hold or toggle), "fast forward now", mute while fast forwarding, volume |
| Cheats | Toggle codes, type a new one with the keyboard, or import a `.cht` file from `cheats/<console>/` |
| Display | Screen size (Fit, Pixel perfect, Stretch) and look (Sharp, Smooth, LCD grid, CRT lines). DS: screen layout. |
| Controls | The in-game buttons for this console |
| Screenshot | Saves a BMP to `screenshots/<console>/` |
| Restart | Resets the game after confirming |
| Save and quit | Writes the automatic save and returns to the library |

Speed and Display settings apply to **this game** or **all games**. Per-game settings
are stored in `saves/<console>/<game>.options`.

On-screen messages show the fast-forward speed, a rewind bar, save confirmations and,
on the first launch, a one-time tip about the menu button.

ZR / ZL still quick-save and quick-load Slot 1. N64 keeps Minus + ZR / ZL, because ZL is
the Z trigger.

### Per-console notes

| Console | Rewind | Fast forward button | Cheats | Notes |
| --- | --- | --- | --- | --- |
| GBA, GB, GBC (mGBA) | Yes | R3 | Yes | In-process, as before |
| NES, SNES, Genesis, SMS, GG | Yes | R3 | Yes | `core_runner.cpp` |
| DS (melonDS) | No | Menu only (the sticks drive the touch cursor) | Action Replay | Fast forward is limited by the audio queue unless muted |
| DSi | No | Menu only | Action Replay | Save states unsupported, as before |
| N64 (Mupen64Plus-Next) | No (states are too large) | R3 | Yes | The menu draws off-screen and is uploaded to the GL frame. No on-screen messages over the running game. Screen size: Fit or Stretch. |

## v0.5.1: speed options

- **Performance boost** (Speed page and Settings > Gameplay, off by default): raises
  the CPU to 1785 MHz while a game runs and restores the previous clock when it is
  turned off or the game closes (`cpu_boost.h`, clkrst on firmware 8.0+ or pcv on older
  firmware). The clock is re-applied every 3 seconds, because HOME and docking can
  reset it. It means more heat and battery use.
- **DS 3D rendering** (Display page on DS, and Settings > Gameplay): *Two cores* turns on
  melonDS's threaded software renderer. It was previously forced off. The setting is
  read when the game starts, so a change applies on the next launch. If a game is
  unstable, switch to *One core*.
- Frame skip was considered and left out: melonDS 0.9.3 has no internal frame skip, so
  skipping in the frontend would only skip presenting frames, not producing them.
- Not yet measured on hardware. JIT for melonDS is a separate experiment.

## v0.5.2: Nintendo 3DS (experimental)

- New console **Nintendo 3DS (experimental)**: decrypted `.3ds`, `.cci` and `.cxi` dumps go in
  `roms/3ds/`. `.cia` files are installers and are not listed. The console needs full-memory
  application mode, like DS and N64.
- Emulator: the unmodified **Dekopon v3.0.0-RC1** release (Azahar-based, GPL-2.0-or-later),
  installed as `cores/dekopon.nro` through the emulator update. See
  `licenses/Dekopon-NOTICE.txt` for the exact binary hash and source.
- AI1 Emu starts Dekopon with the game path, and Dekopon boots it directly. Dekopon has its
  own in-game menu (+ and −), save states, cheats, layouts (R3) and per-game options.
  Dekopon keeps its data in `/switch/dekopon/`.
- Known limits of using the release as-is: quitting a 3DS game returns to the Homebrew Menu,
  not AI1 Emu. AI1 Emu's own menu, slots and performance boost do not apply. Play time is not
  counted (the launch is recorded so the game appears in "Recently played"). Fixing these
  needs our own Dekopon build, which needs NXVK built in a Linux container or WSL.
- Some games need 3DS system files from your own console (for example, shared fonts).
  None are included.

## v0.5.3 and v0.5.4: fixes from the first 3DS and DS tests

- The Library lists every console. Consoles with games come first, and an empty console shows
  where its files go. 3DS also accepts compressed `.zcci` / `.zcxi`.
- 3DS games already in Dekopon's folders are listed too: `/switch/dekopon/roms/` plus the
  `roms_dir` / `roms_dir_2` folders in `/switch/dekopon/config/config.ini`.
- DS sound no longer cuts in and out when a game runs below full speed. The old queue
  paused the audio device on every underrun until ~0.1 s had refilled, which caused on/off
  chopping several times a second. Playback now continues, and blocks are stretched by up to
  1.35× while the queue is low (slightly lower pitch, no gaps).
- The emulator update skips files that are already identical on the SD card (same size and
  SHA-256), so a change to one emulator downloads only that file.
- 3DS sound depends on Dekopon itself, because the release binary is unmodified. Its own audio
  settings (+ and − in a game) are the only adjustment until we build Dekopon ourselves.

## v0.5.5 to v0.5.13: test-channel builds

All of these went to the private test channel only. Known problems are tracked in
[KNOWN-ISSUES.md](KNOWN-ISSUES.md).

- **0.5.5:** every console filter fits in one row (3DS was off-screen), sort shown in the
  footer. DS audio keeps a steady speed: a 2-second speed estimate drives a smoothed,
  continuous resampler instead of per-block stretching.
- **0.5.6:** touch scrolling keeps its position and glides with momentum; covers decode
  on a background thread; text sizes are prepared at startup.
- **0.5.5 and 0.5.6 did not start on a Switch.** The Windows compiler wrote drive paths
  (`E:/...`) into dependency files, make misread them, and `main.cpp` was not rebuilt
  after `library_ui.h` changed. The two halves disagreed on the library's memory layout.
- **0.5.7:** the Makefile rewrites those paths, and the build is clean. Debug symbols for
  every published build are archived from here on.
- **0.5.8:** Dekopon's background shader building was switched on automatically. This
  caused red Pokémon models in Pokémon Ultra Sun and was **removed in 0.5.12**.
- **0.5.9:** missing covers download from libretro-thumbnails, including 3DS. Update
  checks run when the app opens and every 5 hours. Networking is shared by the updater,
  cheats and covers (`network.cpp`).
- **0.5.10:** a startup log in `logs/app.log`. Network work waits until the library is on
  screen, and covers wait for the update check.
- **0.5.11:** fixes a black screen on start when a large game exists twice (for example a
  3DS game in both `roms/3ds/` and Dekopon's folder). Games over 64 MB are compared at
  32 sample points instead of byte by byte.
- **0.5.12:** AI1 Emu no longer changes Dekopon's settings.
- **0.5.13:** Performance boost also covers 3DS: AI1 Emu writes a sys-clk profile for its
  own title (CPU 1785 MHz, memory 1600 MHz) when a 3DS game starts with the boost on, and
  removes it when the app opens again. A sys-clk profile you made yourself is never
  changed.

## Files and arguments

- New sources: `ui_kit.*` (theme, shapes, icons, text), `app_data.*` (settings, themes,
  history, favourites, cheats, slots), `game_session.*` (menu, slots, rewind, fast
  forward, cheats, display, messages) and `keyboard.h` (Switch software keyboard).
  `library_touch.cpp` was folded into `library_ui.cpp`.
- Slot files: `<prefix>.auto.state`, `<prefix>.state` (Slot 1), `<prefix>.slotN.state`,
  each with a `.bmp` picture alongside.
- Core NRO arguments: `<core> <game> <root> <platform> <play|resume> <cover>`. Older
  cores ignore the two new arguments, and new cores default to `play` when they are
  missing.
- Emulator NROs now carry a small RomFS with the menu fonts (about 350 KB).
- Fonts are subset to Latin-1 with fontTools: M PLUS Rounded 1c (Medium, Bold, ExtraBold),
  Rubik and Nunito instanced from their variable fonts, plus Geist Mono for cheat codes.
  All are SIL OFL 1.1, with license texts in `romfs/` and `licenses/`. Unbounded and Geist
  Regular/SemiBold were removed.

## Verified

- Built with devkitA64 GCC 16.1.0 on Windows (MSYS2): `AI1Emu.nro` (17.2 MB) and all five
  companion NROs (fceumm, snes9x, genesis-plus-gx, melonds, mupen64plus-next).
- Host tests (MinGW, `scripts/run-host-tests.sh`): touch/controller input, artwork,
  storage scan, the new game-session test (quick save/load, overwrite confirmation, load
  undo, fast forward, rewind, restart, per-game settings, auto save, play history),
  platform detection, duplicates and the update manifest all pass.
- Every screen was captured from the Windows preview (`AI1Emu-Preview.exe --capture`),
  which uses the same SDL2 drawing code. Its game picture is generated, because the
  preview does not emulate.

## Not verified

- Nothing has run on a Switch yet: frame pacing, fast forward speeds, rewind memory and
  CPU cost, the N64 software-rendered menu, swkbd in applet mode, touch, and battery and
  clock readouts.
- The in-app updater still replaces only `AI1Emu.nro` (plus the N64/DS cores in their
  existing special cases). Installing v0.5 needs the complete package, so every emulator
  NRO gets the menu. Updating the updater and the Cloudflare channel is separate work.
