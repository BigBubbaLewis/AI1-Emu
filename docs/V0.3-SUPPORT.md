# AI1 Emu v0.3.2 — multi-console release

v0.3.2 adds the verified-copy legacy folder merge described in `V0.3.2-MERGE.md`
and public source collaboration described in `COLLABORATING.md`. The owner
reported DS working on the original Switch with v0.3.1; its companion binaries
are retained. Folder migration remains untested on physical Switch hardware.

## v0.3.1 DS and artwork corrections

The user reported a black screen and no Plus+Minus response with DS in v0.3.0 on an original Switch. This candidate has NOT yet been retested there. Bulk/chunked ROM reads replace byte-at-a-time input; loading stages are displayed. DS uses conservative aliasing flags, no host networking and no threaded software renderer. Firmware/cartridge load failures now return errors rather than claiming success; direct-boot FreeBIOS/generated-firmware fallback remains supported. Pending DS SRAM is flushed on unload.

Plus+Minus is polled during ROM reads and within the DS CPU frame loops. Frames that run over five seconds can abort cooperatively. This cannot recover a low-level graphics/SD driver hang. Startup phases and core errors are written to `logs/core-nds.log` (DSi: `logs/core-dsi.log`) in the selected data folder. If DS still fails, return with the Switch HOME button and inspect that log. Full-memory application mode is required; the AI1 HOME tile is appropriate.

The DBI cover tool now chooses between `ai1emu` and legacy `retroverse` using all supported ROM extensions and recursive folders, matching the app's preference. It prints the selected folder and transfers artwork there. Replace old PC-tools copies with this version. No existing ROMs, saves or covers are moved.

The actual DS software core was exercised on Windows with a synthetic homebrew cartridge: video/audio callbacks, state round trip and unload passed. A deliberately invalid BIOS was rejected. These host tests do not establish real-game compatibility or Switch performance.

This build compiles for Nintendo Switch using the installed devkitA64 16.1.0 toolchain. It has NOT been gameplay-tested on physical hardware. The user's previous v0.2.2 GBA build worked on an original Switch; this does not verify the new cores, chainloading, performance, audio, saves, states or touch mapping. No overclocking calls are made.

## Installation

Extract `AI1-Emu-v0.3.2-Switch-Package.zip` into the SD root and merge folders. The main file must be `/switch/ai1emu/AI1Emu.nro`, and all four companions must be in `/switch/ai1emu/cores/`. Keep existing ROMs, saves, covers and metadata. Use Homebrew Menu application mode/full memory, or the existing AI1 Emu HOME forwarder. The HOME forwarder still targets the same main filename. Atmosphère and Homebrew Menu are not included.

The v0.2.2 backup is `backups/AI1-Emu-v0.2.2-working-before-v0.3.zip`. Copy its main NRO back to roll back. Keep a separate backup of your SD saves before testing. New v0.3 save states are not promised compatible with older core versions.

Fresh installations need the complete package, because the updater installs only the main NRO. Existing v0.3.1+ installations can update to v0.3.2 through Settings: their working companions are retained. Older GBA-only installations retain the stable v0.2.2 update channel. Full source and packages are published at https://ai1emu-updates.freegamez.workers.dev/ .

## Included integrations

| Console | Core | Accepted uncompressed extensions | Firmware |
| --- | --- | --- | --- |
| Game Boy Advance | mGBA, in main app | `.gba` | Built-in replacement; optional own `system/gba/gba_bios.bin`; old root `gba_bios.bin` still supported |
| Game Boy | mGBA, in main app | `.gb` | Optional own `system/gb/gb_bios.bin` |
| Game Boy Color | mGBA, in main app | `.gbc`, color-capable `.gb` header | Optional own `system/gbc/gbc_bios.bin` |
| NES | FCEUmm companion | `.nes` | None for standard cartridges; FDS is not exposed |
| SNES | Snes9x companion | `.sfc`, `.smc` | Standard cartridges need none; special enhancement-chip games may need user-dumped coprocessor data in `system/snes/` |
| Genesis / Mega Drive | Genesis Plus GX companion | `.md`, `.gen`, `.smd`; `.bin` with SEGA header or in `roms/genesis/` | None for standard cartridges; Sega CD/32X not exposed |
| Master System | Genesis Plus GX companion | `.sms` | No mandatory BIOS for ordinary cartridges |
| Game Gear | Genesis Plus GX companion | `.gg` | No mandatory BIOS for ordinary cartridges |
| Nintendo DS — experimental | melonDS Libretro, software interpreter | `.nds` | FreeBIOS fallback included upstream. For better compatibility use own `bios7.bin`, `bios9.bin`, `firmware.bin` in `system/nds/` |
| Nintendo DSi — experimental | same melonDS core, DSi mode | `.dsi`, DSi-only `.nds` header, or `.nds` under `roms/dsi/` | Own `dsi_bios7.bin`, `dsi_bios9.bin`, `dsi_firmware.bin`, `dsi_nand.bin` in `system/dsi/`; optional own `dsi_sd_card.bin` |

Copy games into `/switch/ai1emu/roms/`, optionally inside console subfolders. Folders are scanned recursively. DS-enhanced cartridges normally run in DS mode; place them in `roms/dsi/` to request DSi mode. Installed DSiWare title management is not implemented. `.3ds`, `.cia`, N64, PS1, PSP and ZIP archives are not scanned. No ROMs or proprietary BIOS/firmware/NAND are supplied.

DS uses the older Libretro melonDS 0.9.3 tree with an existing libnx build target. Its Switch AArch64 JIT is disabled upstream because of memory issues. AI1 therefore uses software rendering and the interpreter. Full speed is NOT promised, and demanding games may be unsuitable at normal clocks. DSi save states are explicitly unsupported by this core; normal game saves use its own save handling. Native [RSDuck melonDS Switch](https://github.com/RSDuck/melonDS/tree/switch) is an older standalone frontend rather than a drop-in library. The Libretro integration preserves AI1's library while isolating that core in a companion executable.

## Controls and layouts

Library: D-pad/left stick navigate, A play, X cover/cartridge, Y title sort, B back, L/R tabs, Plus/Minus settings, ZL/ZR console categories. Category chips also accept touch. The existing smooth touch carousel is retained.

Gameplay: normal face buttons/D-pad/L/R; Plus Start and Minus Select. Hold Plus+Minus to return. ZR saves one state and ZL loads it, where the core supports states. DS: click left stick to cycle side-by-side, stacked and top-screen-focused layouts. Touch maps only into the displayed bottom screen. Docked: move the right stick to move the bottom-screen cursor, click right stick to touch. Microphone input, cameras, wireless and peripherals are not implemented; games requiring them may be incompatible.

## Saves and artwork

New saves are under `saves/<console>/<filename>.<relative-path-hash>.sav`, with `.state` and `.lastplayed` alongside. The path hash separates identical filenames in different folders. Existing flat GBA saves for ROMs directly in the old ROM folder are reused. Do not rename/move a game if you want to retain its hashed save path without manually migrating the associated files. DS/DSi saves are managed inside the game's unique `.files/` directory, using the upstream core's `.sav` format.

If the new folder has no games and the legacy `/switch/retroverse/roms/` does, the library continues using that legacy data folder. Companion executables always live in `/switch/ai1emu/cores/`; they receive the selected data folder explicitly. Nothing automatically moves or deletes user data.

Artwork and metadata use `covers/<console>/<ROM stem>.png|jpg|jpeg`, `artwork-cache/<console>/<canonical release title>.png`, `metadata/<console>/<ROM stem>.txt`, and `screenshots/<console>/<ROM stem>.png|jpg|jpeg`. Existing flat GBA paths remain supported. Custom artwork takes precedence and is never overwritten.

`PC-tools/Prepare-Artwork.cmd` uses the adjacent package folder, or accepts a `switch/ai1emu` folder argument. It needs Windows PowerShell 5.1, not Node.js. With DBI's MTP responder, run `PC-tools/AI1Emu-Automatic-Covers-DBI.cmd`: it recursively reads filenames and transfers only artwork/metadata, never ROMs. Existing covers are skipped. Matching uses per-console release databases, checksums when actual local ROM bytes are available, then exact and normalized regional filenames. DBI cannot verify checksums or read header-only platform distinctions; use `.gbc` for color games and `roms/dsi/` for DSi mode when preparing via DBI. Matching may be ambiguous, ROM hacks may remain unknown, and thumbnails may be absent. An unavailable download leaves the professional fallback; it never blocks gameplay. PC downloads are personal caches; no commercial covers are bundled.

## Licenses and build architecture

mGBA MPL-2.0 stays in the main executable. FCEUmm GPL-2.0, melonDS GPL-3.0, Snes9x's noncommercial license and Genesis Plus GX's noncommercial license are kept in separate executables, each linked only to its own core and the common MIT runner. See bundled upstream license files; the whole package is for noncommercial distribution. Source, build changes and dependency source archives accompany the package in `Source-notices/` to satisfy source redistribution requirements. They are not runtime requirements and may remain on the PC. They contain no keys, games or firmware.

Build with `DEVKITPRO` set to the installed SDK root, then `bash scripts/build-multi-switch.sh`. Upstream revisions are recorded in each `vendor/*/AI1-UPSTREAM.json`; standalone VFS source helpers were enabled for the four companions because RetroArch normally supplies those symbols. Genesis also needed `SWITCH=1` for its older filesystem headers. melonDS explicitly builds with `HAVE_OPENGL=0`. Use a clean core build after changing rendering/platform flags. Existing main-only and Windows-preview build scripts remain available.

## 3DS/2DS investigation — not integrated

[Dekopon](https://github.com/PalindromicBreadLoaf/dekopon) is an Azahar-based native Switch port. 2DS plays the same 3DS game software without stereoscopic 3D, so a separate 2DS core is unnecessary. Its source was inspected at revision `dfba28f5e5342310c1ccff5963363be8512862f6` (GPL-2.0). Its native frontend uses libnx rendering/input/audio and a custom dynarmic-nx dependency. Default graphics require separately built NXVK/libnvk; upstream explicitly says NXVK and switch-mesa cannot be linked together. Its legacy GLES path is marked broken, while a Deko3D path is a separate backend. Required submodules and that graphics/JIT stack are not present in this project's current SDK/source checkout. An optional base Libretro target does not establish that its native Switch GPU/JIT path works as a static AI1 SDL2 core.

Consequently no 3DS executable was built or bundled, no 3DS games are advertised as playable, and no proprietary keys/system files are included. The smallest future solution is a separately built native Dekopon companion with a ROM/return-path interface, then adapting its native dual-screen and virtual-touch controls. That needs a separate integration/build/performance pass; forcing it into the current SDL2/mGBA binary would risk the working build.

## Other future systems — research only

- N64: [Mupen64Plus-Next](https://github.com/libretro/mupen64plus-libretro-nx), with documented [Switch-specific support](https://www.libretro.com/index.php/mupen64plus-next-v2-1/). Requires a tested AArch64 dynamic recompiler and GPU context; renderer/game compatibility and performance vary. Not integrated.
- PS1: [PCSX-ReARMed](https://docs.libretro.com/library/pcsx_rearmed/) is a candidate. Its HLE BIOS fallback has compatibility limits; a user's own BIOS improves compatibility. AArch64 recompiler, disc formats, memory cards and controller mapping need a dedicated integration pass. Not integrated.
- PSP: [PPSSPP lists a completed Switch port](https://www.ppsspp.org/docs/development/porting/). JIT/GPU integration, memory usage and per-game performance require separate work. Not integrated.

## Validation and hardware checklist

Automated host tests cover platform detection, library filtering, legacy save reuse/save isolation, three DS touch layouts, existing touch navigation/inertia, artwork offline matching/custom-art preservation, and updater validation/rollback. Windows preview compiles the same library renderer and captures the actual Cover, Cartridge, Settings and About screens. This does not execute the Switch cores or prove gameplay correctness.

On hardware, test one legal homebrew/owned backup per system: launch; correct picture/aspect; audio over several minutes; all buttons; save in game then exit/reload; state save/load where supported; Plus+Minus return and re-launch another core; library touch/controller navigation; handheld/docked transition; DS bottom touch and all layouts, virtual touch and DSi firmware failures. Test at normal clocks. Retain v0.2.2 until GBA regression checks pass.
