# AI1 Emu v0.3.5 — library, artwork and DS audio fixes

## Install through the app

Settings > Check for updates > download > install and close. Reopen AI1, then
check again to install the DS audio update. Reopen after each component and
repeat until current. Missing N64 support is offered first if necessary.
The complete ZIP includes all components and the DS audio revision marker.

## Duplicate library entries

The library now shows one entry for byte-identical ROMs on the same console,
even if their filenames differ. It compares sizes, small samples, then full
contents before hiding any copy. Different ROM contents, revisions and consoles
remain separate. The visible copy is selected by existing save/state progress,
using recorded play time when available, save/state timestamps next, then deterministic path order. Every original ROM and save stays untouched.
The most recent duplicate scan report is logs/library-duplicates.txt; it lists
hidden paths and their visible counterpart. Save histories are not merged or
deleted. Empty or unreadable files are not assumed to be duplicates.
Scanning happens once at startup, not repeatedly in the background. Large exact
ROM duplicates can add SD-read time during that scan.

## Pokemon Yellow and enhanced Game Boy artwork

The cartridge header may identify an enhanced .gb game as GBC while its database
and already-cached artwork are in GB. Title identification now falls back across
GB/GBC databases and metadata; cover rendering can use the other GB/GBC cache.
This lets existing cached Yellow artwork display without requiring a fresh
commercial-cover download. Custom artwork priority and game/save paths remain.

## DS audio

A dedicated DS runner retains melonDS software/interpreter emulation, controls,
dual-screen layouts, touch, saves, states and library return. Other companion
runners remain unchanged. Audio now starts with about 96 ms of queued samples,
refills after underruns, and uses bounded back pressure instead of clearing
queued music when the queue grows. Small +/-0.5% frame-clock corrections address
clock drift. Audio is not amplified or normalized. Loading a state discards
only the now-obsolete queued audio and primes playback again.
logs/core-nds.log and core-dsi.log record queue size, underruns and back-pressure
waits every 300 frames. These counters help distinguish buffering problems from
sustained emulation slowdown. No overclock or unverified JIT is enabled.

Automated checks cover exact duplicate identity, save-aware representative
selection, preservation of changed revisions, actual SDL audio queue behavior,
and Yellow artwork rendering through the real UI with an enhanced-GB fixture.
Switch builds and package/source checks are separate from physical testing.
HeartGold and Phantom Hourglass audio improvements still require the owner's
Switch test; buffering does not establish full-speed compatibility or guarantee
that all audio distortion is resolved.

The pre-update main app and DS companion are backed up locally, and the app
updater keeps the replaced companion as cores/melonds.nro.bak.

Additional v0.3.5 validation: the actual Windows melonDS core ran an original
ARM-loop diagnostic cartridge with its audio callbacks routed through DSAudioQueue;
video/audio callbacks, serialization, queue reset after loading a state and unload
passed. This tests integration, not HeartGold/Phantom Hourglass audio quality.
The Windows UI preview uses the shared, updated library and artwork rendering.

The Windows artwork tools now validate automatic cached images, repair invalid caches online, and refill the local personal cache correctly when MTP supplies zero-byte existence markers. Custom artwork remains untouched. The tool prints its version at startup. The embedded consumer engine passed Windows PowerShell 5.1 tests for Yellow cache repair plus Crystal and DK Country downloads, followed by offline cache reuse.
